폰·좌석 태블릿·딜러 화면·전광판 네 단말이 한 상태를 공유하는 오프라인 홀덤 토너먼트 운영 서버입니다. 카드는 사람 딜러가 실물로 돌리고, 칩과 팟, 좌석, 상금은 서버가 관리합니다.

시스템 동작은 README에 있습니다. 이 문서는 왜 그렇게 정했는지를 적습니다.

01동시 접속 한계의 원인 규명과 수용 기준 재정의 7

문제
k6 부하 테스트에서 동시 착석이 11,790명을 넘으면 서버가 종료됐습니다.
원인
컨테이너 512MB 중 114MB가 남아 있었고 OOMKilled=false였습니다. 커널이 아니라 Node(V8)가 기본 힙 상한 259MB에서 스스로 종료한 것이었습니다.
대안
① 인스턴스 증설 — 비용이 선형으로 늘고 원인을 건드리지 않습니다. ② 코드 메모리 최적화 — 범위가 크고 효과가 불확실합니다. ③ 힙 상한 조정 — 컨테이너에 여유가 있어 바로 검증할 수 있습니다.
선택
③. --max-old-space-size=340. 컨테이너 512MB에서 OS와 기타를 뺀 여유 안쪽으로 잡았습니다.
결과
동시 착석 11,790 → 12,420명1,380테이블 12,420명까지 수용했습니다. 천장이 열리자 진짜 병목이 드러났습니다. 테이블 하나를 세우는 비용 737ms 중 523ms(71%)가 로그인 bcrypt여서, 로그인 요청에 상한을 두고 수용 기준을 동시 접속자 수가 아니라 초당 입장 수로 다시 정의했습니다.
한계
k6 합성 부하 기준입니다. 장시간 소크 테스트와 탈락·리바인 시나리오는 포함하지 않았습니다. 8

동시 접속 한계의 원인 규명과 수용 기준 재정의 부하 테스트 지연 수치 오측정 원인 규명 테이블 합병 설계 변경 — 서버 재배치에서 OTP 재착석으로 서버 재시작 복구 재설계 테이블 상태 쓰기 경로 단일화 도메인 규칙에 어긋나는 구현 제안 기각 하지 않기로 한 것 증명하지 못하는 것 검증 규모 에이전트가 읽을 문서 설계
  1. 메타 줄 = md frontmatter(period·role·links)에서 뽑는다. stack은 여기 안 넣음 — README 몫.
  2. 제목 = 명사형 개조식. 무엇을 했는지가 제목만으로 읽힌다. 비유·반전형 제목(「정원을 깎던 것은…」) 대신. 태그 칩은 삭제.
  3. 라벨 6개: 문제 · 원인 · 대안 · 선택 · 결과 · 한계. 원고의 **문제** — … 줄을 렌더러가 dl로 바꾼다. 본문은 합니다체. 「한계」만 한 단계 흐리게.
  4. 판단 번호 01·02 = 라벨 열과 같은 폭에 모노로. 번호·라벨·본문 시작선이 세로로 맞는다. 결과 첫 줄 전후 수치 = 원고에 측정값이 있을 때만, 없으면 줄 자체가 없다 (예: 테이블 합병 설계). 목차 = ## 헤딩 자동 생성. 오른쪽 목차 제목들은 새 톤으로 바꾼 예시 (원문 내용 기준).
