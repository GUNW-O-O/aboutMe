## MR.Brain-Edu

2026.06 – 08 · 단독 (코드 밖 산출물 포함)

전시장 키오스크에서 관람객이 설명 없이 만지는 뇌 해부 교육 데스크톱 앱입니다. 주제와 제공 방식만 받았고, 무엇을 만들지 정하는 일부터 혼자 맡았습니다.

- **SaMD 해당 여부를 기준으로 기능 범위를 먼저 정했습니다.**
  - 「화면 영상의 측정·수치화 금지」를 에이전트 지침에 명문화했습니다
  - 수치는 공개 문헌의 집단 평균만 출처와 함께 보여 줍니다
- **제품 용도와 맞지 않는 데이터를 공개 데이터셋과 자체 보유 데이터로 전환했습니다.**
  - 오픈소스 라이선스를 표시하면서 데이터 사용 조건(DUA)도 조사했습니다
- **무인 운영을 전제로 관람객 세션을 경계로 삼았습니다.**
  - 방치되면 초기 화면으로 돌아갑니다
  - 아무도 만지지 않은 메인화면이 스스로 초기화되던 문제는 실제 조작이 있을 때만 초기화 시계를 켜도록 바꿔 풀었습니다
  - 빌드타임 플래그를 런타임 관리자 설정 화면으로 옮겼습니다

### 저사양 전시 기기의 로딩·프레임 최적화

**문제** — 전시장 미니 PC에서 챕터 진입이 느리고 줌인할 때 프레임이 떨어졌습니다. 소프트웨어만 파는 것이 기본이라 고객 기기 사양은 제각각입니다.

**선택** — 저사양 기기를 타깃으로 못 박고 로딩과 프레임을 따로 다뤘습니다.
- **로딩**: 화면 캔버스를 하나로 합치고 단면 영상의 화질 단계를 낮췄습니다
- **프레임**: 렌더 화질과 투명 표현을 관리자 설정으로 빼 기기에 맞춰 고르게 하고, 기본값을 가볍게 하고, 줌 범위를 통일했습니다

**결과** — `챕터 로딩 4.9초 → 1.6초` 전시용 미니 PC(Ryzen 5 3500U)에서 최적화 전후 빌드를 같은 자동 시나리오로 5회씩 돌린 값입니다.
- 챕터2 평균 26fps → 58fps, 챕터3 엽 조작 42fps → 59fps
- 메모리 최대 2.1GB → 1.1GB

## BrainDS

2026.06 · 공유 레포에서 리포트 뷰어와 구조 분석 파이프라인 담당

Orthanc(DICOM 서버) 기반 의료영상 분석 플랫폼의 웹 리포트 뷰어 계층입니다.

- **분석 결과를 통째로만 지울 수 있던 구조에서, 결과 파일 단위로 조회·삭제·재생성하도록 바꿨습니다.**
  - 파일별로 서버와 로컬에 있는지 보여 주고, 빠진 것만 다시 만듭니다
  - 로컬을 먼저 지우고 실패하면 서버를 건드리지 않아 웹에서 다시 시도할 수 있습니다
  - 서버에는 없고 로컬에만 남은 캐시는 지우고 다시 받습니다
- **시리즈마다 따로 보내던 상태 조회 요청을 한 번으로 줄였습니다.**
- **구조 분석을 세그멘테이션 · 3D · PDF 세 단계로 나눠 단계별로 실행할 수 있게 했습니다.**
  - 어느 단계까지 끝났는지 상태에 남깁니다
- **외부 Slicer 연동을 걷어내고, 메시를 서버에서 만들어 브라우저 3D 뷰어로 보게 했습니다.**
  - MRI 오버레이 리포트 뷰어를 새로 만들었습니다

## 영상 제작 루프

2026.09 – 진행 중 · 단독

책 홍보, 강연, 유튜브에 사용한 영상을 만드는 루프를 설계했습니다. 한 편이 요약 → 대본 → 음성 합성 → 자막 → 컷 설계 → 프롬프트 → 생성 → 잇기·자막 입히기를 지납니다. 처음에는 단계마다 사람이 승인했습니다. 지금은 에이전트가 채점하고 반복 작업은 스크립트가 맡아, 사람은 돈이 드는 생성 앞뒤와 완성본에만 들어옵니다.

- **에이전트마다 읽을 것과 읽지 않을 것을 정해 컨텍스트를 설계했습니다.**
  - 작업 문서를 입구 문서 하나와 필요할 때만 펴는 문서들로 나누고, 역할별 「열지 않는 것」을 적었습니다
  - 채점 에이전트에는 채점에 쓰는 네 절만 잘라 넘깁니다(3만 6천 자 → 8천 자). 앞 원고의 점수와 쓴 쪽의 의도가 새지 않습니다
- **에이전트가 손으로 옮겨 적던 일을 스크립트로 넘겼습니다.**
  - 뼈대는 스크립트가 채우고, 에이전트는 장면과 프롬프트 본문만 씁니다
- **자동화해도 품질이 떨어지지 않게, 지킬 규칙은 코드로 걸고 판단은 예시로 남겼습니다.**
  - 있던 규칙을 어기면 문서에 줄을 더하지 않고 프롬프트 검사 코드(린트)에 넣습니다. 문서는 한 번 읽히고 끝나지만 코드는 매 실행마다 다시 읽힙니다
  - 돈이 드는 생성 직전에는 무조건 사람을 부르고, 다시 뽑을 컷도 사람이 고릅니다
- **사람의 지적을 채점 기준으로 옮기고, 기준을 계속 고쳐 나가는 방식을 정했습니다.**
  - 승인 8편의 로그에서 [what-i-decided](https://github.com/GUNW-O-O/what-i-decided)로 사람의 지적을 뽑아 감점 항목으로 만들었습니다
  - 채점 점수가 사람의 판단과 어긋나면 대본이 아니라 채점하는 쪽을 고쳤습니다

## mri2mesh

2026.07 – 08 · 단독

MRI를 올리면 세그멘테이션을 거쳐 영역별 3D 메시(GLB)를 뽑는 로컬 워크벤치로, MR.Brain-Edu가 쓰는 에셋을 생산합니다. 라이브러리마다 메시 생성 알고리즘이 달라 어떤 방식이 나은지 비교하고, 에셋을 편하게 만들고, 익명화하려고 만들었습니다.

- **임상 분석 파이프라인은 익명화를 하지 않아, 에셋 파이프라인에서 메타데이터를 지워 익명화했습니다.**
  - 익명화가 실패하면 진행을 멈추고, 세그멘테이션이 끝나면 원본을 지웁니다
- **노화 교육 목적을 지키려고, 메시 스파이크의 원인 라벨(백질 저신호)을 빼지 않고 본체와 끊어진 파편만 걸렀습니다.**
  - 노화와 함께 늘어나는 소견이라 빼면 노화 교육에서 보여 줄 것이 사라집니다
  - 59조각 중 노이즈 46개를 걸러 13조각만 남겼습니다
