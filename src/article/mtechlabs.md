## 영상 제작 루프

2026.09 – 진행 중 · 단독

책 홍보, 강연, 유튜브에 사용한 영상을 만드는 루프를 설계했습니다. 한 편이 요약 → 대본 → 음성 합성 → 자막 → 컷 설계 → 프롬프트 → 생성 → 잇기·자막 입히기를 지납니다. 처음에는 단계마다 사람이 승인했고, 지금은 에이전트가 채점하고 반복 작업은 스크립트가 맡아, 사람은 돈이 드는 생성 앞뒤와 완성본에만 들어옵니다.

- **에이전트마다 읽을 것과 읽지 않을 것을 정해 컨텍스트를 설계했습니다.**
  - 영상 한 편을 만드는 동안 읽는 작업 문서가 4만 자를 넘어, 입구 문서 하나와 필요할 때만 펴는 문서들로 나누고 역할별 「열지 않는 것」을 적었습니다. 쓰는 쪽이 채점표를 보고 맞춰 쓰지 못하게 막는 역할도 합니다
  - 채점 에이전트에는 한 편의 작업 파일에서 채점에 쓰는 네 절만 잘라 넘깁니다(3만 6천 자 → 8천 자). 읽는 양과 함께 앞 원고의 점수와 쓴 쪽의 의도가 새지 않게 막습니다
  - 채점 에이전트를 매번 새로 띄우면 채점 기준을 다시 읽느라 토큰이 들고, 앞 원고에서 반려한 점이 고쳐졌는지 확인할 수 없어서 한 편이 끝날 때까지 같은 에이전트를 씁니다
  - 문서 무게를 매번 읽는 것과 필요할 때 읽는 것으로 나눠 스크립트가 층마다 상한을 셉니다. 상한에 맞추려 사례를 깎자 있던 규칙의 실수가 되풀이돼, 매번 읽는 문서만 작게 두고 필요할 때 읽는 조각은 상한을 올렸습니다
- **에이전트가 손으로 옮겨 적던 일을 스크립트로 넘겼습니다.**
  - 같은 대사를 세 곳에 옮겨 적는 데 한 편마다 출력 토큰이 수천 들었고, 한 글자만 틀려도 채점이 다른 대사로 매겼습니다. 뼈대는 스크립트가 채우고 에이전트는 장면과 프롬프트 본문만 씁니다
  - 음성은 고친 문단만 다시 뽑아, 이미 컷에 맞춘 다른 문단의 길이가 바뀌지 않게 했습니다
  - 컷을 이어 붙이기 전에 길이를 재서 계획과 다르면 멈춥니다. 96초 계획이 86초로 나와 그림이 말보다 5~8초 앞선 일이 있었습니다
- **자동화해도 품질이 떨어지지 않게, 지킬 규칙은 코드로 걸고 판단은 예시로 남겼습니다.**
  - 한 세션에서 제가 짚은 여섯 가지 중 다섯은 이미 문서에 있던 규칙이었고, 가벼운 검수 에이전트도 부정문을 통과시켰습니다. 문서는 한 번 읽히고 끝나지만 코드는 매 실행마다 다시 읽힙니다
  - 그래서 있던 규칙을 어기면 문서에 줄을 더하지 않고 프롬프트 검사 코드(린트)에 넣어, 걸린 컷은 생성 명령이 보내지 않습니다. 코드로 걸 수 없는 판단만 잘된 예시 한 줄로 남깁니다
  - 대본은 메인 에이전트, 컷은 채점 에이전트, 프롬프트는 가벼운 검수 에이전트가 봅니다. 컷이 명쾌하면 프롬프트는 결과로 판별되므로 점수 없이 기계적 검수만 둡니다
  - 기호가 읽히는지는 채점이 못 봐서, 돈이 드는 생성 직전에는 무조건 사람을 부르고 다시 뽑을 컷도 사람이 고릅니다
- **사람의 지적을 채점 기준으로 옮기고, 기준을 계속 고쳐 나가는 방식을 정했습니다.**
  - 승인 8편의 로그에서 [what-i-decided](https://github.com/GUNW-O-O/what-i-decided)로 사람의 지적을 뽑아 감점 항목으로 만들었고, 같은 지적이 두 번 나오면 기준이 부족한 것으로 봅니다
  - 기계적으로 세던 채점표를, 에이전트가 무엇을 하면 더 좋아지는지 적은 긍정문 채점표(연관성·흡입력·물음표)로 다시 세워 틀에 맞추지 않고 더 창의적으로 쓰게 했습니다
  - 작업 로그에는 규칙으로 못 내린 것만 두고, 내리면 지웁니다
  - 사람이 고친 문장·컷뿐 아니라 에이전트가 잘 만든 것도 예시로 쌓아, 루프가 스스로 나아지게 했습니다
  - 채점 점수가 사람의 판단과 어긋나면 대본이 아니라 채점하는 쪽을 고쳤습니다. 대본은 요약부터 쓰고, 영역 이름만 아는 상태로 대사를 읽다가 물음표가 들면 반려하는 단계를 뒀습니다

## MR.Brain-Edu

2026.06 – 08 · 단독 (코드 밖 산출물 포함)

전시장 키오스크에서 관람객이 설명 없이 만지는 뇌 해부 교육 데스크톱 앱입니다. 주제와 제공 방식만 받았고, 무엇을 만들지 정하는 일부터 혼자 맡았습니다.

- **SaMD 해당 여부를 기준으로 기능 범위를 먼저 정했습니다.**
  - 「화면 영상의 측정·수치화 금지」를 에이전트 지침에 명문화했습니다
  - 수치는 공개 문헌의 집단 평균만 출처와 함께 보여 줍니다
- **오픈소스 라이선스를 표시하면서 데이터 사용 조건(DUA)도 조사해, 제품 용도와 맞지 않는 데이터를 공개 데이터셋과 자체 보유 데이터로 전환했습니다.**
- **무인 운영을 전제로 관람객 세션을 경계로 삼았습니다.**
  - 방치되면 초기 화면으로 돌아갑니다
  - 아무도 만지지 않은 메인화면이 스스로 초기화되던 문제가 있었습니다
  - 메인화면은 실제 조작이 있을 때만 초기화 시계를 켜도록 바꿨습니다
  - 빌드타임 플래그를 런타임 관리자 설정 화면으로 옮겼습니다

### 저사양 전시 기기의 로딩·프레임 최적화

**문제** — 소프트웨어만 파는 것이 기본이라 고객 기기 사양이 제각각인데, 전시장 미니 PC에서 챕터 진입이 느리고 줌인할 때 프레임이 떨어졌습니다.

**선택** — 저사양 기기를 타깃으로 못 박고 로딩과 프레임을 따로 다뤘습니다.
- **로딩**: 화면 캔버스를 하나로 합치고 단면 영상의 화질 단계를 낮췄습니다
- **프레임**: 렌더 화질과 투명 표현을 관리자 설정으로 빼 기기에 맞춰 고르게 하고, 기본값을 가볍게 하고, 줌 범위를 통일했습니다

**결과** — `챕터 로딩 4.9초 → 1.6초` 전시용 미니 PC(Ryzen 5 3500U)에서 최적화 전후 빌드를 같은 자동 시나리오로 5회씩 돌린 값입니다.
- 챕터2 평균 26fps → 58fps, 챕터3 엽 조작 42fps → 59fps
- 메모리 최대 2.1GB → 1.1GB

## mri2mesh

2026.07 – 08 · 단독

MRI를 올리면 세그멘테이션을 거쳐 영역별 3D 메시(GLB)를 뽑는 로컬 워크벤치로, MR.Brain-Edu가 쓰는 에셋을 생산합니다. 라이브러리마다 메시 생성 알고리즘이 달라 어떤 방식이 나은지 비교하고, 에셋을 편하게 만들고, 익명화하려고 만들었습니다.

- **임상 분석 파이프라인은 익명화를 하지 않아, 에셋 파이프라인에서 메타데이터를 지워 익명화했습니다.**
  - 익명화가 실패하면 진행을 멈추고, 세그멘테이션이 끝나면 원본을 지웁니다
- **노화 교육 목적을 지키려고, 메시 스파이크의 원인 라벨(백질 저신호)을 빼지 않고 본체와 끊어진 파편만 걸렀습니다.**
  - 노화와 함께 늘어나는 소견이라 빼면 노화 교육에서 보여 줄 것이 사라집니다
  - 59조각 중 노이즈 46개를 걸러 13조각만 남겼습니다

## BrainDS

2026.06 · 공유 레포에서 리포트 뷰어와 구조 분석 파이프라인 담당

Orthanc(DICOM 서버) 기반 의료영상 분석 플랫폼의 웹 리포트 뷰어 계층입니다.

- **분석 결과를 통째로만 지울 수 있던 구조에서, 결과 파일 단위로 조회·삭제·재생성하도록 바꿨습니다.**
  - 파일별로 서버와 로컬에 있는지 보여 주고, 빠진 것만 다시 만듭니다
  - 로컬을 먼저 지우고 실패하면 서버를 건드리지 않아, 웹에서 다시 시도할 수 있습니다
  - 서버에는 없고 로컬에만 남은 캐시는 지우고 다시 받습니다
- **시리즈마다 따로 보내던 상태 조회 요청을 한 번으로 줄였습니다.**
- **구조 분석을 세그멘테이션 · 3D · PDF 세 단계로 나눠 단계별로 실행할 수 있게 했습니다.**
  - 어느 단계까지 끝났는지 상태에 남깁니다
- **외부 Slicer 연동을 걷어내고, 메시를 서버에서 만들어 브라우저 3D 뷰어로 보게 했습니다.**
  - MRI 오버레이 리포트 뷰어를 새로 만들었습니다
